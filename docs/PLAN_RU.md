# План эксперимента v0.2.0

## Центральный вопрос

Проверить, совпадает ли ранжирование блоков по удобству обратимого встраивания с ранжированием по эмпирическому риску обнаружения. Если нет, разработать и проверить распределитель нагрузки, который учитывает оба фактора.

## Жёсткое разделение данных

- `train` — только обучение вспомогательных и финальных детекторов;
- `validation` — только выбор payload levels и `alpha`;
- `test` — только финальный результат.

После создания `frozen_payloads.json` и `frozen_allocator.json` их нельзя менять в рамках v0.2.0.

## Сравниваемые стратегии

1. raster — базовый порядок блоков;
2. random — детерминированная случайная перестановка;
3. predictability — только высокий `P_i`;
4. detectability — только низкий `D_i`;
5. joint — `alpha P_i - (1-alpha)D_i`.

Сравнение выполняется при одинаковой **accounted net bpp**.

## Основные метрики

- exact cover recovery;
- exact message recovery и BER;
- gross bits / sideinfo bits / accounted net bits;
- PSNR / SSIM;
- ROC-AUC;
- TPR@5% FPR;
- Spearman/Kendall между `P_i` и `D_i`;
- median и bootstrap 95% CI;
- encode/decode latency;
- число использованных блоков и изменённых пикселей.

## Независимый стеганоанализ

В v0.2.0 используются два разных класса детекторов: SRM-inspired residual/co-occurrence logistic (`SRM-lite`) и residual CNN. Детектор, формирующий `D_i`, к финальной паре не относится. Дополнительно предусмотрен adaptive SRM-lite, переобучаемый на конкретную стратегию.

## Ограничения, которые нужно честно оставить в статье

- side information пока учитывается, но хранится как инженерный sidecar;
- `SRM-lite` не является полным SRM;
- compact CNN не заменяет проверку полноценным SRNet, если журнал/рецензенты её потребуют;
- текущий QF95 256x256 набор является BOSSbase-derived JPEG, а не оригинальным lossless BOSSbase;
- обнаружимость оценивается эмпирически конечным набором детекторов.
